
# v2.5c 분석 — 의존성 깊이와 Planner 읽기

## 가설과 검증

**가설:** 체인이 뒤로 갈수록 파일 1개에서 파생되는 참조가 늘어난다

**검증 결과:** 부분적 일치. 단, 더 정확한 모델은:

**정제 가설:** 의존성 깊이가 깊은 번들은 Planner 읽기를 비선형적으로 증가시킨다

## 핵심 비교: 같은 4파일, 다른 결과

| 구성 | 파일당 proj import | 토큰/파일 | 비율 |
|------|-------------------|----------|------|
| v2.5b C1 (Layer 0, 4파일) | 0.5 | 11.5K | 1x |
| v2.5c C2 (Layer 1+2, 4파일) | 1.0 | 91.5K | **8x** |

import 수 2배 → 토큰 8배 = **비선형 확산**

## 비선형 확산 모델

```
의존성 깊이 d, 분기 수 b일 때 Planner 읽기량 ≈ O(b^d)

Layer 0: b=0.5, d=1 → O(1)     = 7-12K/file
Layer 1: b=1.0, d=1 → O(2-3)   = 15-17K/file  
Layer 2: b=1.0, d=2 → O(4-5)   = 18-24K/file
Layer 1+2 combined: b=1.5, d=2 → O(9) = 91K/file ← 기하급수
```

## 실제 Planner 행동

| 번들 | turns | brief→input 비율 | 행동 |
|------|-------|-----------------|------|
| Layer 0 (4파일) | 6-8 | 7-8x | Target Files만 읽음 |
| Layer 1 (3파일) | 7-8 | 7-11x | Target + DI 읽음 |
| Layer 2 (2파일) | 8-10 | 9-14x | Target + DI + 연쇄 읽기 |
| Layer 1+2 (4파일) | **41** | **81x** | 타겟+DI+테스트+연쇄 전부 읽음 |

## 결론

분할 전략은 파일 수가 아니라 **의존성 깊이** 기준이어야 함.
같은 4파일이어도 Layer 0은 12K/file, Layer 1+2는 91K/file (8배 차이).

**분할 규칙:** 의존성 깊이별로 분할하면 각 체인이 선형 유지.
여러 레이어를 하나의 체인에 묶으면 비선형 폭발.
