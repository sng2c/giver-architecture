# 통제 실험: 모놀리식 vs Giver v2.2

> 동일 과제, 동일 인력, 동일 환경에서 모놀리식 방식과 Giver v2.2를 비교한 통제 실험 결과.

## 실험 설계

| 항목 | 모놀리식 | Giver v2.2 |
|------|----------|-----------|
| 과제 | Redis 프록시 10개 모듈 구현 | 동일 |
| 판정 | 113개 테스트 통과 | 113개 테스트 통과 |
| 산출물 | 540줄 (10개 파일) | 498줄 (10개 파일) |
| 방식 | 단일 에이전트가 전체 구현 | Giver가 Scout→Planner→Scout→Worker 체인으로 위임 |
| 세션 | 1개 연속 대화 (76턴) | 1개 Giver 세션 + 4개 체인 |
| 컨텍스트 관리 | 누적 (매턴 전체 대화 재처리) | `context:"fresh"` (각 에이전트 초기화) |

이 실험은 PTT 프로젝트의 관측 데이터와 달리 **동일 과제·동일 환경**에서 수행된 통제 실험이다.

## Giver v2.2 체인별 상세

| # | 과제 | Planner | Scout | Worker | 합계 | 이상적 |
|---|------|--------:|------:|-------:|-----:|:------:|
| 1 | 4개 기초 모듈 | 49K 🟢 | 34K 🟢 | 489K 🟠 | 572K | 2/3 |
| 2 | 3개 코어 모듈 | 3,297K 🔴 | 25K 🟢 | 213K 🟠 | 3,536K | 1/3 |
| 3 | 3개 코어 모듈 (재시도) | 153K 🟡 | 51K 🟢 | 170K 🟡 | 374K | 1/3 |
| 4 | 3개 서버 모듈 | 11K 🟢 | 34K 🟢 | 83K 🟡 | **129K** | **2/3** |

### 2번 체인 컨텍스트 누수

Planner 입력 3,297K는 Previous Failures 섹션에 이전 체인 결과가 요약 없이 전체 포함되어 발생. 정상적인 giving of pain은 간결한 실패 요약만 포함해야 함. 이 누수를 제외하면 Giver 정상 합계는 1,074K.

### 점진적 개선

| 체인 | 합계 | 1차 대비 | 비고 |
|------|-----:|---------:|------|
| 1차 | 572K | — | Worker 파일 생성 실패 |
| 2차 | 3,536K | — | Planner 컨텍스트 누수 |
| 3차 | 374K | -35% | Previous Failures 포함 |
| 4차 | **129K** | **-77%** | ✅ 가장 효율적 |

giving of pain이 실패 경험을 효과적으로 전달하면서 4차 체인이 1차 대비 77% 절감 달성.

## 모놀리식 vs Giver 비교

### 방식의 본질적 차이

모놀리식은 단일 에이전트가 모든 컨텍스트를 누적한다. 매 턴마다 이전 대화 전체를 재처리하므로, 대화가 길어질수록 입력 토큰이 선형 증가한다. Giver는 각 에이전트가 초기화된 상태에서 시작하므로 컨텍스트가 격리된다.

### 측정 가능한 지표

| 항목 | 모놀리식 | Giver v2.2 |
|------|----------|-----------|
| 과제 달성 | ✅ 113/113 | ✅ 113/113 |
| 산출물 규모 | 540줄 | 498줄 |
| 세션 수 | 1 (연속) | 1 + 4체인 |
| 총 턴 수 | 76 | Giver 45 + 서브에이전트 118 |
| 컨텍스트 관리 | 누적 | Fresh (격리) |
| 실패 시 격리 | ❌ (이전 컨텍스트 오염) | ✅ (새 체인으로 재시도) |
| 토큰 측정 | 서브에이전트 없어 측정 불가 | 서브에이전트 아티팩트로 정확 측정 |

### 모놀리식 토큰 추정

모놀리식 세션 로그에 API 토큰 데이터가 없어 정확한 측정이 불가하다. 누적 컨텍스트 모델에 따르면:

- **관측 데이터 없음:** 단일 에이전트 세션은 서브에이전트 아티팩트를 생성하지 않아 토큰 분해가 불가
- **누적 특성:** 76턴의 연속 대화에서 매 턴 전체 컨텍스트를 재처리
- **v1 베이스라인 근사:** 유사 과제(10파일 수정)에서 모놀리식 Worker 평균 1.9M. 코딩 테스트(10파일 생성)는 이보다 중간 복잡도로 추정

### Giver v2.2 실측치

| 항목 | 토큰 |
|------|-----:|
| 서브에이전트 총합 | 4,610K |
| 누수(2번 체인 Planner) 제외 | 1,074K |
| 최적 체인(4차) | 129K |
| 최적 체인 이상적 비율 | 2/3 (🟢🟢🟡) |

## 발견된 문제

### 1. Planner 컨텍스트 누수 (2번 체인)

Planner 입력 3,297K. Previous Failures 섹션에 이전 체인의 Worker 결과 전체가 포함됨.

**해결:** SKILL.md에 "이전 실패 결과는 간결한 요약만 포함" 규칙 추가 필요.

### 2. Worker 파일 생성 미흡 (1번 체인)

Worker가 파일을 직접 생성하지 않고 진행 보고서를 작성. 3번 체인부터 "CRITICAL: You MUST write actual .ts source files to disk" 경고가 추가됨.

**해결:** Worker 브리핑에 파일 생성 강조 규칙 추가.
