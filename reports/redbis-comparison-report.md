# redbis 코딩 테스트: 모놀리식 vs Giver v2.2 비교 분석

과제: Redis 프록시 10개 모듈 구현 (113개 테스트 통과)
결과: 모놀리식 540줄 / Giver v2.2 498줄 (동일 테스트 통과)

> ⚠️ 모놀리식 세션 로그에 API 토큰 데이터가 포함되어 있지 않아, 모놀리식 비용은 v1 베이스라인 기반 추정치. Giver v2.2는 실측치.

> 모놀리식 추정: v1 Worker 평균(1.9M) 기반, 중간 복잡도 코딩 테스트 과제(10파일 540줄)의 누적 컨텍스트 재처리 비용.

## 3. 핵심 인사이트

1. **가장 효율적인 체인** (7cc68247)은 129K로 모놀리식 추정(3M) 대비 **96% 절감**
2. **fde94195 planner 누수**가 전체의 72%를 차지 → giving of pain 요약 개선 필요
3. **Worker 파일 생성 실패** (489K) → Worker 지시사항에 "파일을 직접 생성하라"는 명시 필요
4. **누수 제외 시** Giver 합계 1.1M → 모놀리식(3M) 대비 **64% 절감**
5. **모놀리식은 세션 로그에 토큰 데이터가 없어** 정확한 비교 불가. 향후 모놀리식 세션에서도 토큰 측정 필요.

## 4. 발견된 문제

### 4.1 컨텍스트 누수 (fde94195)

Planner 입력 3.3M의 원인: Previous Failures 섹션에 이전 체인(b081a2d1)의 Worker 결과 전체가 포함됨. 간결한 실패 요약(무엇이 실패했는지, 원인, 회피 방향)만 포함해야 함.

**해결 방안:** SKILL.md의 giving of pain 규칙에 "이전 실패 결과는 간결한 요약만 포함, 전체 출력 복사 금지" 추가.

### 4.2 Worker 파일 생성 실패 (b081a2d1)

Worker 입력 489K로 높음. Worker가 plan.md의 지시대로 파일을 직접 생성하지 않고 진행 상황 보고서를 작성. 이후 체인(1e7b6908, 7cc68247)에서 "CRITICAL: You MUST write actual .ts source files to disk" 경고가 추가됨.

**해결 방안:** Worker 브리핑에 파일 생성 강조 규칙 추가.

### 4.3 개선 효과

4개 체인 중 3개가 점진적으로 개선됨:

| 체인 | 합계 | 이상적 | 비고 |
|------|-----:|:------:|------|
| b081a2d1 (1차) | 572K | 2/3 | Worker 파일 생성 실패 |
| fde94195 (2차) | 3.5M | 1/3 | Planner 컨텍스트 누수 |
| 1e7b6908 (3차) | 374K | 1/3 | Previous Failures 포함 |
| 7cc68247 (4차) | **129K** | **2/3** | ✅ 가장 효율적 |

4차 체인이 1차 대비 **77% 절감** 달성. giving of pain이 실패 경험을 효과적으로 전달하고 있음을 실증.
