# Giver 아키텍처 성능 비교 리포트 — 모놀리식부터 v3.6.2까지

**측정 지표**: 최종 컨텍스트 크기 = 입력 + 출력 (에이전트가 처리한 총 정보량)

## 1. 개요

Giver 아키텍처 v1부터 v3.6.2까지의 성능 진화를 종합 분석한다. 각 버전은 구조적 개선을 통해 토큰 효율과 안정성을 개선했다.

**핵심 지표**: P_ctx(Planner 컨텍스트), W_ctx(Worker 컨텍스트), W_ctx_max(Worker 최대 컨텍스트) — 에이전트가 실제로 처리한 총 정보량.

|------|------|-----------|------|

### 4.3 감소 요인 분석

- **W_ctx −52%**: `[Read from:]` 프리픽스로 Worker 템플릿에서 불필요한 지시문과 fallback 로직이 제거됨. no-op Worker도 파일을 찾는 즉시 종료.
- **W_act −33%**: 활성 Worker만 보면 감소폭이 작아짐. no-op Worker 제외 시 실제 작업량은 비슷.
- **W_ctx 최대 −51%**: v3.6.1의 과 점수치(a15cee3f: 11.5KB)가 해소됨.
- **P_ctx −34%**: `[Write to:]` 프리픽스가 "in the chain directory" 지시를 대체.

## 8. 잔존 과제

1. **대형 과제 검증**: v3.6.2 실험이 4건(단순 과제 1 포함). 10K+ Task #0에서의 W/P ratio 추가 검증 필요.
2. **v3.6.2 샘플 확대**: 현재 4체인. 통계적 유의성을 위해 10+ 체인 필요.
3. **Worker 과다 읽기 원인**: W/P > 15x 체인(4건)은 여전히 존재. Planner 큐레이션 부족(P_input < 100K)이 주요 원인.
4. **plan.md 부산물**: `output:"plan.md"`로 인해 Planner 출력이 plan.md로도 저장됨. 해로움은 없으나 pi-subagents 수정으로 제거 가능.

## 9. 결론

v3.6.2는 **task 파일 경로 문제를 근원적으로 해결**하여 체인 안정성과 효율을 모두 개선했다:

- **안정성**: cwd 잔여 파일 간섭 위험 제거, 0666bc7a 사고 재발 불가
- **효율**: 최종 컨텍스트 크기 감소 (W_ctx −52%, W_act_max −50%)
- **일관성**: `[Write to:]` / `[Read from:]` 프리픽스로 경로 관리를 pi-subagents에 위임

모놀리식 대비 **57% 토큰 절감**(v3.5 기준) + **안정성 확보**(v3.6.2)가 최종 성과다.
