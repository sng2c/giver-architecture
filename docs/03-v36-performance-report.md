# Giver 아키텍처 전체 버전 성능 리포트

**핵심 지표**: 에이전트 1회 실행당 컨텍스트 크기(입력 + 출력).  
과제가 복잡하면 턴이 많고 총 토큰도 커지는 건 당연하다. **1회 실행당 컨텍스트**가 구조 효율성의 진짜 지표다.

## 10. 잔존 과제

1. **측정 단위 통일**: v1~v3.5는 토큰, v3.6+는 바이트. 동일 과제에서 토큰/바이트 동시 측정 필요.
2. **대형 과제 검증**: v3.6.2가 4건. W_ctx_max가 10KB+인 과제에서 추가 검증 필요.
3. **W_ctx 이상치 원인**: v3.6.1에서 W_ctx > 8KB인 체인 4건. Planner 큐레이션 부족.
4. **plan.md 부산물**: `output:"plan.md"` 내용은 사용되지 않으나 해로움도 없음.
